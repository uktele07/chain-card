# 設計メモ

何を決めたか、なぜそう決めたか、何を見送ったかの記録。2026年11月16日時点。
数値の現在値は `data/cards.json` が正。ここには理由と経緯を書く。

## 1. ゲームの核

手札4枚が △○✕□ にランダムで割り当てられ、対応するボタンで出す。カードはレベル順（C→B→A→S）にしか出せず、Sは強いがなかなか出せない。敵はリアルタイムで攻撃してくる。

- プレイヤーにレベルはない。成長は装備、アイテム、デッキで出す（ジョブは未着手）。
- 1戦は30〜60秒。
- 対象はゲームパッド（PlayStation配置）。キーボードでも遊べる。タッチ操作は外した。

## 2. 確定したルールと理由

### チェイン

| ルール | 理由 |
|---|---|
| 出せるのは、同じレベル・1つ上・1つ下・C | 「AのときにBを出したい」という要望から。特例にせず一律にした。結果としてAのときは全レベルを出せる |
| チェインは手札をまたいで持続する | 手札ごとにリセットすると、SはC・B・A・Sが1手札にそろったときしか出せず、死にカードになる |
| チェインタイマーは4秒。切れるとチェインなし | 人が遊ぶには3秒だと短いとの感想。シミュレーション上は2.5〜5秒で結果がほぼ変わらない（同レベルを出せば回復するため） |
| Sを出すとチェインはなくなる | 持ち主の指定。Sの連発を防ぐ |
| スキップ（入れ替え）するとチェインが1段下がる | Sを「手札には来るが出せない」ものにするため。毎回下げる案は、うまく使い切っても損をするので見送った |

### 入れ替え時間

| 場面 | 時間 | チェイン |
|---|---|---|
| スキップ | 1.0秒 | 1段下がる |
| 出せるカードがないときの自動入れ替え | 0.35秒待ち＋0.65秒＝合計1.0秒 | 1段下がる |
| キープを残して使い切り | 0.5秒 | 下がらない |
| 4枚すべて使い切り | 0.5秒。最後の1枚がアタックなら +1 ダメージ | 下がらない |

- 自動入れ替えの0.35秒は、配られた手札が一瞬で消えて何が起きたか分からなくなるのを防ぐため。合計を1.0秒より長くすると不利が出すぎる、という持ち主の判断。
- 使い切りボーナスは +3 だと敵が大幅に楽になった（ドラゴンの勝率35%→92%）。+1 で元の難しさに戻る。

### キープ

- 十字キーで、対応する方向のカードをキープ。スキップしても残る。
- キープ以外を使い切れば「使い切り」扱い。こうしないと、キープ中は毎回スキップが必要になり、チェインが毎手札で下がってキープが使い物にならない。
- キープしたカードは、入れ替えの待ち時間中も出せる。

### カード

- アタックは28枚で固定（C13・B8・A5・S2）。威力は武器で決まる。
  - 固定にした理由: Sの枚数が強さを一番左右する。自由にすると全員が上限まで積み、選ぶ余地がなくなる。敵の強さもこの配分が前提。
- スペルは4種から2枚まで（重複不可）。入れなければデッキは28枚まで減る。
  - 効果は「次に出すアタックに乗る。重ね掛け可」。手札が替わっても残る。
  - ダブル（2回当てる。音と表示も2回）、レベルX（レベル無視）、ドレイン（与えた分回復）、ランクアップ（1段上として扱う。出せるかは元のレベルで判定）。
- スペルは最初から全種持っている（ショップ商品にする余地あり）。

### アイテム

- デッキには入れない。3枠にセットし、L2で切り替え、R2で使う。それぞれ1戦に1回。同じ物は1つだけ。
  - デッキに入れていた時期は、種類が多くて戦闘中に読み切れず、使いたい瞬間に来ない問題もあった。
  - 重複を許すと回復薬×3が生存面で飛び抜けた（ドラゴンの勝率56%→95%）ので禁止した。
- 入力の硬直中や入れ替え中でも使える。

### 装備

- 武器はレベルごとの威力を決める。防具は被ダメージを減らす（最低1）。アクセサリーは枠だけある。
- 3つの武器は横並びの強さで、遊び方で選ぶ。斧は遅い人向け（待機が読む時間と重なる）、弓は速い人向け。
- 強くなる実感は防具が担う（銀の胸当てでドラゴンの勝率58%→95%）。
- デュランダルと魔法の衣は、データだけあり入手できない。

### 敵と記録

- 敵は1体ずつ。行動を上から順に繰り返し、行動ゲージが溜まると攻撃する。
- 強い攻撃は、サイレン・画面の縁の赤い点滅・残り1.5秒からのカウントダウン音で知らせる。「敵の技名を見ている余裕がない」という感想から。
- 攻撃パターンは、討伐前は技名だけ。討伐すると間隔とダメージが出る。
- 前の敵をすべて討伐すると、次の敵が出現する（魔王、理の神）。
- ランクは討伐タイムだけに付ける（S・A・B・C）。基準は敵ごとにシミュレーションから決める。
- 無敵（テスト用、タッチパッド）を使った戦闘は、記録も戦利品も付かない。
- 負けたら同じ敵に再挑戦できる。

### お金

- 討伐のたびに戦利品が1個。ショップで売ってお金にし、武器と防具を買う。
- 売買は確認画面を挟む。売るときは個数を選べる。

## 3. 画面で決めたこと

- 戦闘中の情報は、視線がカードから離れなくても入るようにする。これが画面設計の一番の原則。
  - チェインは手札4枚の中央。上に見出し、中に現在の段、下にスペルの記号。
  - 自分のHPは手札の下。アイテムは左、敵の絵は右、敵の名前・HP・行動ゲージは上の中央。
  - 経過時間、Sの回数、ミスの回数は戦闘中に出さない。
- 開始前は手札を伏せる。○で開始し、○のカードは出ない。✕で戻る。
- OPTIONSは、どの画面でも「その場のメニュー」。戦闘中はポーズで、手札と敵のゲージを隠し、再開は1秒のカウントを挟む。
- 決定は○、戻るは✕。灰色の項目はカーソルが飛ばす。
- 絵は図形で描いた代役。アイテムの絵は線画（3案から持ち主が選んだ）。戦闘中のアイコンは小さく控えめに。

## 4. 見送った案と理由

| 案 | 見送った理由 |
|---|---|
| 命中率、デバフ、全体化 | 持ち主が「一旦シンプルに」と整理。全体化は敵が1体ずつになったので外した |
| マナなどのコスト制 | 管理する数字が増えて速度が落ちる。レベル順がコストの役割を担っている |
| 長押しで溜める | 0.5秒単位で出すゲームで、止まって待つ操作は流れを切る |
| 位置取りや移動 | 別のゲームになる |
| ガードボタン、ジャストガード | 提案したが採用されていない。防御はアイテムと防具が担う |
| 次の手札の予告 | 提案したが採用されていない。Sの引き運への対処は、キープとチェインの実が担う |
| スタンのスペル | 次に選ぶカードが何でもよく、選ぶ意味がない。閃光弾（アイテム）に形を変えた |
| 3連戦 | 敵を一覧から選ぶ方式に変えた。連戦はダンジョンで戻す予定 |
| 毒瓶、身代わり人形 | 押す判断がない |
| 斧の入れ替え+0.5秒 | 剣より弱くなる。待機0.5秒だけで十分な罰 |
| Unity | 持ち主はAIに任せられる度合いを重視。全部がコードで完結するブラウザ向け（TypeScript + Phaser）にした。家庭用ゲーム機に出すなら移植が要る |

## 5. シミュレーションについて

`npm run sim` は、本番と同じ `battle.ts` を自動プレイヤーに遊ばせる。腕前は「1枚出すのにかかる秒数」で表す（初心者0.8秒、普通0.5秒、上級0.3秒）。この数字は仮定で、実測ではない。

**自動プレイヤーの癖（結果を読むときに割り引くこと）**

- ミスをしない。人が遊ぶと、数字より厳しくなる。
- 斧でも、威力0のCを普通に出す。人が工夫すれば斧はもっと強い。
- スペルを来た順に使う。ドレインを回復が要らない場面でも使う。
- Sをキープするが、スペルはキープしない。

**今の基準（初期装備、普通の腕前、アイテムは回復薬・閃光弾・チェインの実）**

| 敵 | 勝率 | 狙い |
|---|---|---|
| スライム、ゴーレム | 100% | 練習相手 |
| ドラゴン | 6割前後 | 装備を整えたくなる壁 |
| 魔王 | 2割前後 | 装備と腕が要る |
| 理の神 | ほぼ0%。店の最良の装備で3割前後 | 最後の目標 |

**分かっている弱点**

- スペルを0枚にしても2枚にしても、勝率がほとんど変わらない。スペルが弱いのか、自動プレイヤーの使い方が下手なのか、切り分けができていない。
- Sは1戦に3回前後出ており、当初の「そうそう出せない」よりは多い。

## 6. 保留中の論点

- **スペルの効き目**（上記）。自動プレイヤーを人の遊び方に近づけてから判断する。
- **アクセサリー**: ダンジョンの初回踏破の報酬にする。1つ目は炎の指輪。ほかは未定。
- **お金の流れ**: 今はスライムを繰り返し倒せば貯まる。何をいつ買える想定にするか未設計。イベントでの調達も未実装。
- **敵の個性**: 5体は数値と攻撃の間隔が違うだけ。仕掛けのある敵（ボタンを封じる、手札を入れ替える、など）は未着手。
- **ジョブ**: 当初の構想にあるが未着手。武器と役割が重なるので、どちらで個性を出すかを決める必要がある。
- **命中補正と回避補正**: 当初の構想にあるが、命中率をなくしたので使い道がない。
- **入力処理の分割**: `GameScene.ts` の半分はボタンの処理。画面が増えたら分ける。
- `data/cards.json` の `rules.deckSize` は使っていない（デッキは28〜30枚）。

## 7. ダンジョン（すごろく）

2026年11月16日に決定。最初に作るのは火の神殿だけ。水・風・魔王城は、盤面と敵を足す形で後から作る。

### 進み方

- サイコロ1個で進む。止まったマスで何かが起きる。通り過ぎたマスは何も起きない。
- 分かれ道あり。新しい画面は出さず、盤面の上で行き先のマスを強調して選ぶ。
- 中ボスとボスのマスは必ず止まる。
- 1つのダンジョンは10分ほど（当初15分と言っていたが、まず10分で作る）。盤面は約60マス。
- 逃げる手段はない（後で、逃げられるアイテムを足すかもしれない）。

### マス

| マス | 内容 |
|---|---|
| 何も起こらない | |
| モンスター | 止まるたびに、その神殿の雑魚からランダム。雑魚に仕掛けはない |
| 回復 | HPを20回復 |
| 最大HPアップ | +10（その場で10回復）。ダンジョンの外に出ると元に戻る |
| アイテム | 使用済みのアイテムが1つ復活 |
| イベント | ダンジョンごとに1種類。火の神殿は3ダメージ |
| ランダム | 上のどれかが起きる |

### 持ち越しと負け

- HPとアイテムの使用状況は、戦闘をまたいで持ち越す（アイテムは探索全体で各1回）。チェインは持ち越さない。
- 負けると入口から。中ボスを討伐した後は中間地点から。
- マスに止まるたびに自動で保存し、開き直すと続きから。
- 雑魚を倒すと、売れる物を1個落とす（討伐と同じ）。

### ボスと報酬

- 仕掛けはボスに付ける（雑魚には付けない）。火はやけど（戦闘中、時間でHPが減る）、水は手札が勝手に入れ替わる、風はボタンの配置が入れ替わる、が案。
- 初回の踏破報酬はアクセサリ。火の神殿は「炎の指輪」（使い切りボーナス +1 → +3）。2回目以降は300G。
- 踏破の画面は報酬だけを出す（残りHPや戦闘回数は出さない）。討伐タイムのランクは付けない。

### 画面

- 入口は、敵を選ぶ画面に「討伐 / ダンジョン」の切り替えを足す。右側は説明文を出さず、ダンジョンの絵だけ。
- 盤面は全体を出さず、自分の周りを映してスクロールする。□で「先を見る」モード。左下に小さな全体図。
- 盤面の絵は「神殿の石床」（レンガの壁、四角い石の床、直線と直角、まっすぐな溶岩）。
  - 最初の案は、岩肌のまだら模様と丸く光る溶岩が「少し気持ち悪い」と言われた。有機的な形と質感は避ける。
  - 見送った案: フラット（色面だけ）、古い地図（羊皮紙にインク）。
- 見送った形式: 一本道の連戦、分岐マップ（道順を選ぶ）、歩くマップ、一歩ずつ進む、タイムアタックの塔。移動カードで進む案も出したが、持ち主はサイコロ1個を選んだ。

### あとから持ち主が決めたこと

- サイコロは二段階。○で回り始め、もう一度○で止まる。回っている間は✕でやめられる。
  - 回っている間の目は飾りで、止めた瞬間に抽選する（目押しはできない）。こちらの判断。
- 分かれ道では、いまの出目で止まるマスを道ごとに強調する（「止まる」の札）。
- マスの絵柄の意味を見る画面（盤面で△、またはメニューの「マスの説明」）。

- 入口（最初のマス）にいる間だけ、盤面のメニューから装備を変えられる（持ち主の指示）。負けて入口に戻ったときも変えられる。中ボス討伐後に戻る中間地点では変えられない。
  - それ以外の場所では、これまでどおり変えられない。

### 実装でこちらが決めたこと（持ち主の了承は、まだ取っていない）

- 戦闘の途中でポーズから外に出ると、負けた扱い（入口か中間地点に戻る）。負けそうな戦闘をやり直す抜け道をふさぐため。盤面から出るのは自由で、続きから再開できる。
  - ブラウザを閉じた場合は、戦闘前のHPでその敵からやり直せる。抜け道だが、ふさいでいない。
- ダンジョンの中では、装備とアイテムを変えられない（戦闘前の画面でメニューを開けない）。外に出れば変えられる。
- 「何も起こらない」マスは表示を出さず、すぐ次のサイコロへ。回復などの表示は約2秒で自動で閉じる（○でも閉じる）。
- 「最初からやり直す」は、押し間違いを防ぐため2回押して実行。
- 炎の指輪は、手に入れたとき、アクセサリが空なら自動で装備する。
- サイコロを振った時点で保存する（開き直しての振り直しはできない）。
- 最大HPアップは探索の状態（`save.run`）にだけ持たせている。外の戦闘には出ない。踏破・敗北・やり直しで消える。

### 戦闘中の背景（決定済み・未実装）

**この節は、見た目の方針を作り直す前の決定。** いまの見た目（`docs/look.md`）では、背景は弱くぼかして暗く沈め、敵だけに光を当てる。「ダンジョンは神殿の広間」という題材は生きているが、明るさや描き方は `docs/look.md` に従う。討伐用の抽象の背景（C）をどうするかは、新しい見た目で見本を出して決め直す。

- ダンジョンの戦闘は「A 神殿の広間」（盤面と同じ世界。レンガの壁、柱、石の床、奥に溶岩）。
- 討伐の戦闘は「C 抽象」（景色なし。敵の色の光と、細い同心円・放射線）。敵ごとに色だけ変える。
- 見送り: 「B 火山の遠景」（色面の重なり）。
- 実装は後回しと言われている。合図があってから。作り方: 960×540 の絵を `art.ts` で作り、`drawBattle` の最初に層0へ `image()` で置く。手札と枠が読めるよう、全体を暗くして縁を落とす（見本は黒 50% を重ねた）。
- 見本を作ったスクリプトは作業用の場所にあり、残らない。上の説明から作り直すこと。

### 配信先（目標は Steam。後々）
- Steam（PC）: ページをアプリに包む道具（Electron など）で出せる。軽い。
- スマホ: 包む道具（Capacitor など）で出せるが、タッチ操作の画面を作る必要がある。
- 家庭用機: ウェブの技術がそのままでは動かない。別エンジンへの作り直しか移植の依頼が要る。これが本命なら、早めに Godot か Unity へ移るほうが安い。
- ルール（`battle.ts`、`dungeon.ts`）、数値データ、テストは描画と切り離してあるので、移すときの元にできる。
